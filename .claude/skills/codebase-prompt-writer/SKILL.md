# 코드베이스 맞춤 프롬프트 작성

사용자가 프롬프트 작성을 요청하면, 일반론적인 프롬프트가 아니라 **현재 코드베이스에 실제로 맞는** 프롬프트를 작성한다.

## 1. 요청 파악

- 프롬프트의 목적(어떤 작업을 시킬 것인지)과 대상(다른 에이전트/모델/사람)을 파악한다.
- 목적이 불분명할 때만 짧게 질문한다. 코드에서 알아낼 수 있는 것은 묻지 않는다.

## 2. 코드베이스 검토 (필수)

프롬프트를 쓰기 전에 반드시 실제 코드를 확인한다. 추측으로 파일명·함수명·명령어를 적지 않는다.

- 프로젝트 개요: `README*`, `CLAUDE.md`, `AGENTS.md`, `package.json` 등 매니페스트, 디렉터리 구조
- 요청과 관련된 실제 파일, 모듈, 함수, 타입, 설정값
- 컨벤션: 언어/프레임워크, 코드 스타일, 네이밍, 테스트 방식, 빌드·실행·테스트 명령어
- 현재 상태: `git status`, 최근 커밋(진행 중인 작업이 있다면 반영)
- 범위가 넓으면 Explore 에이전트로 탐색을 위임해도 된다.

## 3. 프롬프트 작성

다음 요소를 코드베이스 사실에 근거해 채운다(해당 없는 항목은 생략):

- **배경/맥락**: 프로젝트가 무엇이고, 관련 부분이 어떻게 동작하는지
- **목표**: 무엇을 달성해야 하는지 구체적으로
- **관련 파일**: 실제 경로(`path/to/file.ts:123` 형식 권장)와 각 파일의 역할
- **제약/컨벤션**: 따라야 할 스타일, 건드리면 안 되는 부분, 사용하는 라이브러리
- **작업 단계**(필요 시)
- **완료 조건/검증 방법**: 실제 존재하는 테스트·빌드·실행 명령어

작성 원칙:
- 모든 경로·이름·명령어는 검토 중 직접 확인한 것만 쓴다.
- 프롬프트 본문 언어는 사용자가 지정하지 않으면 사용자의 요청 언어를 따른다.
- 군더더기 없이, 받는 쪽이 바로 실행할 수 있는 수준으로 구체적으로.

## 4. 저장 후 Finder에서 띄우기

1. 저장 위치: `~/Documents/prompts/<프로젝트 디렉터리명>/`
2. 파일명: `YYYY-MM-DD-<짧은-영문-slug>.md` (같은 이름이 있으면 `-2`, `-3` 접미사)
3. 파일에는 프롬프트 본문만 넣는다(설명·메타 코멘트 제외).
4. 저장이 끝나면 Finder에서 해당 파일을 선택한 상태로 연다:

```bash
open -R "<저장한 파일의 절대 경로>"
```

## 5. 마무리 응답

- 저장 경로를 알려준다.
- 프롬프트 작성 시 근거로 삼은 핵심 파일과, 판단이 필요했던 가정이 있다면 짧게 언급한다.
